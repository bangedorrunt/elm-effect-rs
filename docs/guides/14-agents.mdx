# Agents

An agent that writes application code reads [Use the APIs](15-use-the-apis.mdx) and then the guide for that task. It reads ADR-0002 when it changes the carrier and ADR-0005 when it changes the durable engine. It reads `skills/elm-effect` when the user says migrate or build an app. It reads [Framework flows](17-framework-flows.mdx) and [`docs/research/state-machines-and-flows.md`](../research/state-machines-and-flows.md) when auditing concurrency or state transitions. It reads [Harel statecharts](18-xstate.mdx) and [`skills/elm-effect/references/statechart.md`](../skills/elm-effect/references/statechart.md) when modeling hierarchical statecharts or actor lifecycles. Extension is [Add a capability](13-add-a-capability.mdx). It is one task, not the whole manual.

## Rules that do not change

* Return `Effect` from library code. Call `Runtime::run` in `main` or in a test.
* Keep `Fail`, `Die`, `Interrupt`, and park apart.
* Put services in tags. Call `provide` at the edge.
* Use `policy` or `Schedule` for retry. Do not sleep in a loop.
* Use `TestClock` in the order fork, adjust, join.
* A `Program::update` is pure. Commands are data.
* Compile statecharts into pure `Program::update` folds via `StatechartProgram`. Do not run a second background scheduler.
* Statechart transitions execute strictly in Law L1 order: Exit(source) -> Actions & Assigns -> Entry(target).
* Eventless `always` transitions cascade in micro-steps until reaching quiescence.
* A durable append uses one `epoch` and one `seq` for one retry of the same append.
* Do not rebuild `.beads/gates.jsonl` from the issues log.
* A sibling removes Resonate only through its own adoption record. `OurEngine` in `elm-effect-durable` replaces it (ADR-0005); do not restore a vendor adapter or add a new one.

## A new module

A module earns its place when a caller uses it. Add the type or function, a test that fails without it, and the guide entry that names it. Do not add a module just to mirror another library's file layout.

## Extension from an application

Add a `ServiceTag`, a `Program`, or a `DurableLog`. Do not add a second scheduler. The guide [Add a capability](13-add-a-capability.mdx) is the full rule.
