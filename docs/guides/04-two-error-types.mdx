# Two error types

`Cause<E>` holds a list of reasons. The reasons stay separate.

| Reason | Meaning | Who handles it |
| --- | --- | --- |
| `Fail` | A typed error `E` | `catch` or `Result` from `Effect::result` |
| `Die` | A defect. A panic at the fiber boundary is a defect | The supervisor. `catch_defect` in rare library code |
| `Interrupt` | The fiber stopped because of cancellation | The runtime. Release still runs |

Park is a fifth outcome. Park is a durable wait. Park is not `Fail` and not `Interrupt`. Read [The durable log](12-durable-log.mdx).

## Catch only the typed error

```rust
let recovered = Effect::fail("missing").catch(|error: &str| Effect::succeed(error.len()));
```

`catch` does not take a defect or an interrupt. `catch_cause` sees all three reasons. Do not call `catch_cause` in business code. The supervisor calls it.

`or_die` turns every typed error into a defect. Do not call `or_die` after a retry. The caller still needs the typed error.

## Exit codes

`Runtime::exit_code` maps an `Exit`.

| Exit | Code |
| --- | --- |
| Success | 0 |
| Typed failure | 1 |
| Defect | 2 |
| Interrupt | 130 |

`Runtime::run_main` runs the effect and then stops the process with that code.
