## Run one description

Call `Runtime::run` for a simple effect in `main` or in a test. Call `Runtime::run_main` when the process must exit. Both run the effect on a fiber, so `with_fiber`, `fork_child`, `race`, `timeout`, and `Effect::all` work at the static edge too. `ManagedRuntime::run` is the same edge when the effect also needs a layer's services and a managed disposal.

```rust
use elm_effect::{Effect, Runtime};

fn main() {
    let exit = Runtime::run(Effect::succeed("ok"));
    let code = Runtime::exit_code(&exit);
    std::process::exit(code);
}
```

`Runtime::new` builds a runtime when `Remote::call` needs a reference. `shutdown` stops live fibers and waits for finalizers. `ManagedRuntime::run` runs the effect on a fiber with the layer's services ambient, and disposes the layer when the runtime drops.

## Build a description

| Call | Result |
| --- | --- |
| `Effect::succeed(value)` | Success `A`. `E` is `Infallible` until you fail |
| `Effect::fail(error)` | Typed error `E` |
| `Effect::die(defect)` | A defect. Not a typed error |
| `Effect::interrupt()` | An interrupt reason |
| `Effect::sync(closure)` | The closure runs when the effect runs |
| `.map(f)` | A new success value |
| `.flat_map(f)` | A next effect after success |
| `.catch(f)` | A typed error becomes a new effect |
| `.catch_tag(tag, f)` | The same, only for a `TaggedError` whose tag matches |
| `.catch_tags(handlers, or_else)` | One recovery per tag, and a fallback for the rest |
| `.tap_error_tag(tag, f)` | Observe one tag, then re-raise the failure |
| `.result()` | `Effect<Result<A, E>, Infallible, R>` |
| `.exit()` | `Effect<Exit<A, E>, Infallible, R>` |

A description does no I/O until `Runtime::run`.

## Small combinators

`pipe!` and `flow!` are macros because a Rust function cannot take a variable number of functions. `pipe!(x, f, g)` is `g(f(x))`. `flow!(f, g)` is `|x| g(f(x))`.

```rust
use elm_effect::{flow, pipe};

let six = pipe!(5, |n: i32| n + 1);
let double = flow!(|n: i32| n + 1, |n: i32| n * 2);
let twelve = double(5);
```

A `flow` head that takes several arguments takes them as one tuple, because a Rust closure has a fixed arity: `flow!(|(a, b): (i32, i32)| a + b, double)((1, 2))`.

## Ask for a service

```rust
let need_db = use_service::<DbTag>();
let ready = need_db.provide::<DbTag, ()>(db.clone());
let exit = Runtime::run(ready);
```

`use_service::<T>` sets `R` to the tag `T`. `provide` removes that tag. Supply the first tag in the tuple first. After 16 tags, use `Cons`.

`Layer::<DbTag, Infallible, ()>::from_value(db)` builds a layer from a value. `layer.build(&scope)` runs the constructors. `layer.fresh()` clears the memo so the next build runs the constructors again. `Layer::provide` rejects a cycle before a constructor runs.

When you have no value to hand — inside an `Interpret`, which is static — close the tag from the runtime's built services instead:

```rust
let layer = Layer::<DbTag, Infallible, ()>::from_value(db);
let runtime = ManagedRuntime::make(&layer);
let ready = use_service::<DbTag>().provide_from(runtime.context().unwrap());
let exit = runtime.run(ready);
```

`provide_from` takes the services out of a `ManagedRuntime` built from a layer. A tag the layer never built is a defect at the run edge, not a default value. `map_err` translates the typed failure channel, which is how `use_service` (always `Infallible`) joins the `E` your `Program` declares. A `Loop` calls `Interpret::interpret_in_env` with its own `context()`, so an interpreter that needs the world overrides that one method and leaves `interpret` alone.

## Acquire and release

```rust
let scope = Scope::new(1);
let resource = scope.acquire_release(
    Effect::succeed(handle.clone()),
    |handle| Effect::sync(move || handle.close()),
);
```

`add_finalizer` registers a closure and `add_finalizer_effect` registers an effect. Both have an exit-aware form: `add_finalizer_with_exit` and `add_finalizer_effect_with_exit` hand the release a `ScopeExit`: whether the body succeeded, failed, or was interrupted, plus its typed-failure count and defects. `close` runs finalizers in reverse order; `close_with` supplies the exit when the caller has one. A closed scope releases the resource at once and returns an interrupt.

## Retry, repeat, and a remote call

```rust
let exit = Runtime::run(retry(
    || load_rows(),
    Schedule::<DbError, u64>::recurs(3),
));
```

`retry` calls the factory again after a typed failure. `repeat` calls the factory again after success. A defect or an interrupt stops both.

```rust
let remote = Remote::new(RemotePolicy::default());
let exit = remote.call(&Runtime::new(), &clock, || load_rows());
```

`call` admits in this order: filter, cache, rate limit, bulkhead. The attempt timeout starts after the bulkhead admits the call. Read the numbers in [Retry and remote policy](08-policy.mdx).

## Many effects

`Effect::all(effects, concurrency)` is the effect-level fan-out: ordered results, at most `n` children alive under `Concurrency::Bounded(n)`, first failure wins after interrupting and releasing the siblings. `Effect::all_discard` drops the values. Both need a fiber, which every runtime edge provides.

The runtime-level `all`, `all_result`, and `for_each` take `&Runtime` and `Body` closures; they are the imperative-shell edge for the same fan-out.

`race` returns the first success. `race_first` returns the first completion. `timeout` races the effect against `Clock`.

`Concurrency::Unbounded` starts every task. Do not pass it to a remote policy.

## A stream

```rust
let stream = from_iter(0..100, 16);
let exit = stream.map(|n| n + 1).take(10).run_collect();
```

`run_fold` consumes the stream. `map_effect` runs an effect per chunk. The `bound` argument is the maximum number of chunks in flight. `cancel` stops the pull.

## A metric

`Metrics` is in the default build. A `Counter`, `Gauge`, `Frequency`, `Histogram`, or `Summary` describes the series; the registry holds the state.

```rust
use elm_effect::{Attributes, Counter, Metrics};

let metrics = Metrics::new();
let hits = Counter::new("app/hits")
    .with_description("Rows read")
    .with_attributes(Attributes::from_pairs([("route", "/rows")]));

metrics.edit(|registry| registry.update(&hits, 1.0));
let table = metrics.read(|registry| registry.dump());
```

`edit` takes the registry mutably. `read` hands it out shared. `update` adds to a counter, `set` and `add` move a gauge, `record` counts a frequency, `observe_histogram` and `observe_summary` take one number. Each has a `_with` form that merges contextual attributes into the series key.

`dump` returns one padded line per series: `name=`, `description=`, `type=`, the attribute set, then the state. Lines are sorted by id and then by attribute text, so the table is stable across runs. An empty registry dumps an empty string. `snapshot` returns the same series as data.

The four hooks write on an exit: `effect.track(&metrics, |exit, registry| ..)` on every exit, `track_errors` on a typed failure only, `track_defects` on a defect only, and `track_duration(&metrics, |elapsed, registry| ..)` measures on the effect's own clock, so a `TestClock` counts virtual time.

## Read config at startup

`Config` describes one value. `load` reads it from a provider, so domain code never touches the environment. Both modules are in the default build.

```rust
use elm_effect::{Config, ConfigError};
use elm_effect::config::Value;
use elm_effect::config_provider::Provider;

let provider = Provider::from_pairs([
    ("HOST".to_string(), "localhost".to_string()),
    ("PORT".to_string(), "8080".to_string()),
]);

let host = Config::string(Some("HOST".to_string())).load(&provider)?;
let name = match host {
    Value::Str(name) => name,
    other => panic!("expected a string, got {other:?}"),
};

let port = Config::integer(Some("PORT".to_string()))
    .with_default(Value::Int(3000))
    .load(&provider)?;
```

The constructors are `string`, `non_empty_string`, `number`, `finite`, `integer`, `boolean`, `literal`, `literals`, `secret`, `redacted`, `duration_ms`, `duration`, `date`, `byte_size`, `url`, `port`, `log_level`, `array`, `all`, `record`, `succeed`, and `fail`. The combinators are `map`, `flat_map`, `map_effect`, `validate`, `or_else`, `or_else_with`, `option`, `with_default`, and `nested`.

`load` answers `Result<Value, Vec<ConfigError>>`: one value, or every error the group found. The kinds are `Missing`, `Invalid`, `Source`, and `Defect`. A failed read (`Source`) and a provider that died (`Defect`) are not absence: neither `with_default` nor `option` recovers them, and only `catch_defect` answers a defect. `load_effect` moves the same load into an effect, so a provider defect arrives as the effect's defect.

`Config` holds `Rc`-bound run closures, so it is not `Send`. Build and load it on the thread that starts the process, then pass the decoded values on.

## A cell

`Ref::new(value)` stores a cloneable value. `get` returns a clone. `update` applies a pure function. The function must not call a service.

`MutableRef` has `set`. `SynchronizedRef::update_effect` runs an effect one time under the permit. `Queue::new(capacity)` is the bound for two tasks. `Semaphore::new(permits)` limits in-flight work.

## A long-lived program

```rust
let mut loop_ = Loop::<App, AppInterp>::boot(&boot);
loop_.send(msg);
let model = loop_.model();
```

`boot` calls `Program::init` and runs the first commands. `send` is the only entrance. `model` reads the fold. `intents` lists durable keys in order. A `Subscriber` has `read` and no write method.

## A durable log

```rust
let log = MemLog::new();
let offset = log.append_json(
    r#"{"v":1,"producer":{"producer_id":"job","epoch":1,"seq":0},"payload":"ok"}"#,
)?;
let rows = log.read_from(&Offset::Start)?;
```

The next new `seq` for that epoch is `last + 1`. The same triple returns the same offset. `Offset::At` that this log did not mint fails with `UnknownOffset`.

## A dispatch plan and a park

```rust
let plan = plan_attempt(None, &cap);
let park = plan_park(until_ms, max_wait_secs, now_ms, None);
```

`None` for the current row means `DispatchNew`. `plan_park` with no ceiling uses 86400 seconds. A larger `max_wait_secs` is `RefusedOverCeiling`. A past `until_ms` is `ResumeNow`. `PendingStore::upsert_pending` writes one park. The same `(run_id, promise_id, park_generation)` writes nothing the second time.

## A cron tick

```rust
use elm_effect_durable::{CronSchedule, fire_key};

let schedule = CronSchedule::parse("30 3 * * 0")?;
let tick_ms = schedule.next_after_ms(now_ms).expect("a 5-field cron has a next tick");
let key = fire_key("weekly-review", tick_ms);
let out = engine.start(&key, now_ms)?;
```

`CronSchedule` is pure and uses UTC with minute resolution. The fields are `minute hour day-of-month month day-of-week`; lists, ranges, steps, and month or weekday names are accepted. `next_after_ms` is strict. `latest_at_or_before_ms(last_ms, now_ms)` is the one-tick catch-up after downtime. The same `fire_key` starts once: a replay re-attaches instead of dispatching the effect twice. The tick is part of the key, so overlapping firings are distinct runs; choose the overlap policy at the host. Registration, pause/resume, catch-up policy, and the tick loop stay with the host. `child_key(parent, step, attempt)` and `step_key(run_key, step)` build deterministic child and step keys and are re-exported from the crate root alongside `fire_key`.

`OurEngine::with_storage(store)` binds a host `EngineStorage`. Every store read and write returns `Result<_, StorageError>`; the engine propagates it as `EngineError::Storage`. `MemStorage` never fails. `with_journal(store, journal)` also binds a persisted `JournalStore`, so a restart re-attaches to recorded intent. `JournalStore` reads and writes return `Result<_, JournalError>`; `InMemoryStore` never fails. A transactional store overrides `commit_run` and `commit_park` to make the run and park one write. `OurEngine::settle` and `claim` project the journal fence onto the run row when the host completes or retries a run; a stale fence returns `None` after projecting the latest journal row, so storage never stays stale. `start_with(key, now_ms, &StartOptions { max_attempts, lease_ms, owner })` sets the journal attempt budget, claim lease, and claim owner (`start` delegates with `StartOptions::default()`). `attempt` counts one provider retry (past `max_attempts` the row dead-letters to `Failed`); `expire_lease(key, now_ms)` times out a dead claim — an `InFlight` / `Accepted` row whose `lease_deadline <= now_ms` settles to `Unknown` (live leases and non-running rows return `None` untouched) — and `reconcile` steps `Unknown -> ReconcilePending -> outcome`, so an expired run recovers without re-dispatching. `RunPhase` serializes to its lowercase wire name (`as_str` / `FromStr` / `ParseRunPhaseError`); `StartOptions`, `StartOutcome`, `ParkOutcome`, `RunStatus`, `EngineMsg`, `RunRow`, and `ParkedRow` also round-trip through serde. A sibling store verifies the port in one call each: `storage_laws(&mut store)` and `engine_laws(&mut engine)` return `(name, outcome)` per law. `park_until` stores the absolute `until_ms`; `max_wait_secs` caps the reported `wait_ms`, not the stored deadline. `park_until` and `wake` refuse an `Unknown` run with `EngineError::Uncertain`; reconcile or cancel it first.

`plan_cron_tick(name, &schedule, policy, last_fired, now_ms)` is the unified entry: `CronPolicy::Latest` runs the latest missed tick once (a new schedule anchors at `now - 60s`, so it only fires when the current minute matches and never replays hours of history it was never registered for); `CronPolicy::Skip { grace_ms }` runs the next tick only while it is still fresh, returning `None` for a stale tick instead of firing late. Both return a `CronFire { key, tick_ms }`; `CronSchedule::plan_tick` is the same choice as a method. Start the returned `key` like any other run: the first start dispatches, a replay re-attaches.

## Join children, roll back a saga, and read the fence

Fan-out keys are data: `child_key(parent, step, attempt)` names one child run, `step_key(run, step)` names one step. Start each child through the engine, then `plan_join` over `(key, phase)` pairs reads the join: `Pending { remaining }` while children run or park, `AllSettled` when every child settles (or when there are no children), `Failed { failed, cancelled, unknown }` when any child fails, cancels, or turns unknown — terminal failure wins over pending, so one bad child short-circuits the join even while siblings still run.

A saga is forward steps plus precomputed compensation keys: `compensate_key(run, step)` names the undo run for one step. Record each finished step as a `SagaStep { step_key, compensate_key, status }`; `plan_saga_rollback` walks them in strict LIFO order and collects the `compensate_key` of every `Completed` step, skipping `Compensated`, `Failed`, and `Skipped` — so a rollback that crashed halfway resumes idempotently and never re-emits a compensation that already ran. The returned `SagaPlan` carries `compensations` in run order; `all_compensated` is true exactly when nothing remains.

The fence reads typed before it acts. `check_claim` answers `Ok(())` or one `ClaimRejection` (`NotFound`, `Terminal`, `StaleGeneration`, `LeaseLive`); `check_settle` answers `Ok(())` or one `SettleRejection` (`NotFound`, `Terminal`, `StaleGeneration`, `IllegalTransition`). The engine's `claim_checked`, `settle_checked`, and `wake_checked` verbs return the same answers as data (`ClaimOutcome::Claimed` / `Rejected`, `SettleOutcome::Settled` / `Rejected`, `WakeOutcome::Woken` / `NotParked`); the plain `claim` / `settle` / `wake` verbs map success to their row and refusal to `None`. `journal_store_all` runs the journal fence suite against any store in one call, the way `engine_laws` and `storage_laws` verify the port.

## Drive the engine from an Elm program

The engine is a synchronous kernel. The host owns it, provides it through a `ServiceTag` (for example `Arc<Mutex<OurEngine<...>>>`), and calls a verb from `Interpret::interpret_in_env` inside `Effect::sync`. `drain_due(now_ms)` returns `EngineMsg::Woke`; map it into the program's `Msg` and let the fold return the next commands. The host reads its `Clock` or `TestClock` at the edge and passes `now_ms`; the engine does not sleep, spawn, or read the clock.

The run key is the host's durable command key and the `DurableLog` `producer_id`. The loop's log records the message outcome; the engine journal records the run fence; settle both when the effect finishes. Retries, timeouts, and remote policy stay in the host's `Interpret` / `plan_attempt` layer.
