# Port the cli zsh completion generator rows

Source rows: `packages/effect/test/cli/completions/completions.test.ts`, Zsh
section (rows `:391`-`:540`, 20 rows).

The pin's Zsh generator (`cli/internal/completions/zsh.ts`) emits a
self-contained `_arguments`-based script from a `CommandDescriptor`. The port
adds `pub mod zsh` to `crates/elm-effect-unstable/src/cli_completions.rs`.

## Witness

`crates/elm-effect-unstable/tests/cli_completions_zsh.rs` — one test per row,
each carrying its upstream line, plus a byte-equality test against goldens
generated by the pin's own `zsh.ts` (committed under
`tests/fixtures/completions/zsh/`).

## Accompanying refactor

The descriptor fixtures were duplicated between the bash and zsh witnesses, so
they moved to `tests/completions_fixtures/mod.rs` and the bash witness now uses
them too. The bash goldens/flags are unchanged, so its 22 tests still pass. The
shared helpers (`sanitize_shell_name`, `alias_form`, `all_flag_forms`,
`completion_function_name`) likewise moved out of `pub mod bash` to the parent
module.

## Scope boundary

Only the Zsh generator. The fish generator (`fish.ts`, ~22 rows), the
`Completions.generate` dispatch (3 rows), and the `ComprehensiveCli`-fixture
rows (`:854` zsh, `:885` fish, `:814` bash) stay unported.

## Why no modules.toml change

`completions.test.ts` is linked to no module in `conformance/modules.toml`, so
flipping these rows moves no module status. Nothing to lease.
