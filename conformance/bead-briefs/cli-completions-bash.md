# Port the cli bash completion generator rows

Source rows: `packages/effect/test/cli/completions/completions.test.ts`, Bash
section (rows `:141`-`:375`).

The pin's Bash generator (`cli/internal/completions/bash.ts`) emits a
self-contained completion script from a `CommandDescriptor`. The port adds
`pub mod bash` to `crates/elm-effect-unstable/src/cli_completions.rs`, reusing
the Unit 6 descriptor model.

## Witness

`crates/elm-effect-unstable/tests/cli_completions_bash.rs` — one test per row,
each carrying its upstream line, plus a byte-equality test against goldens
generated by the pin's own `bash.ts` (committed under
`tests/fixtures/completions/bash/`). Byte equality is stricter than the pin's
`assert.include`.

## Scope boundary

Only the Bash generator. The zsh (`zsh.ts`, ~21 rows), fish (`fish.ts`, ~22
rows) generators and the `Completions.generate` dispatch (3 rows) stay
unported, as do the `ComprehensiveCli`-fixture rows (`:814` bash, `:854` zsh,
`:885` fish) which need the 439-line fixture.

## Why no modules.toml change

`completions.test.ts` is linked to no module in `conformance/modules.toml`, so
flipping these rows moves no module status. Nothing to lease.
